# Reward Sources

How each plan separates economic yield, incentives, fees, costs and platform-funded support.

A displayed reward can have more than one source. The source-attribution sheet for each plan separates them instead of using one universal marketing claim.

| Source class         | Examples                                          | Published attribution                                                    |
| -------------------- | ------------------------------------------------- | ------------------------------------------------------------------------ |
| Network rewards      | Validator or staking emissions                    | Network, validator route, gross reward and slashing exposure             |
| Protocol income      | Borrower interest, savings rate or trading fees   | Protocol, position type, utilisation or fee mechanism and exit liquidity |
| Ecosystem incentives | Time-bound token incentives                       | Sponsor, amount, end date and whether the incentive is guaranteed        |
| Treasury support     | Operational reserve, treasury or marketing budget | Approved budget, maximum amount, period and responsible entity           |
| Other income         | A specifically approved source                    | Contract, risk, accounting treatment and disclosure owner                |

The plan data sheet then shows how gross income becomes a user reward:

**gross realised income + approved incentive − execution cost − impairment − disclosed platform charge = distributable reward**

If one component changes, the source mix and effective date change with it. Historical statements remain available.

## Source-attribution schedule

Every plan version binds a funding schedule containing source identifier, legal counterparty or protocol, asset and network, gross-income recognition rule, cash or token settlement, fee and cost waterfall, budget cap, effective dates and reconciliation account.

Treasury-funded support is posted as a separate expense and user-reward liability. It is never disguised as protocol yield. Unrealised token value is not credited as distributable income until the approved recognition rule is met.

## Sustainability view

The financial dashboard separates realised external income, approved subsidy, reward liability, paid reward, liquidity reserve and uncovered shortfall. A plan stops accepting new positions when its funding, capacity or liquidity rule cannot be met.
