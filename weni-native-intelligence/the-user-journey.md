# The User Journey

A normal WENI interaction moves through six visible stages.

## 1. Establish the goal

The system identifies what the person is trying to understand or do, which asset or protocol is involved, the relevant time horizon, and whether the request is educational, analytical, or action-oriented.

## 2. Define the evidence perimeter

The Agent identifies which sources are required, which sources are available, what the user has consented to share, and which facts remain outside visibility.

## 3. Build a current state

Material data is normalised around the correct network, asset, contract, block, time, account, and product context. Conflicting or stale sources remain visible.

## 4. Explain the situation

The Agent presents what is known, what is inferred, what is uncertain, why it matters, and which assumptions affect the result.

## 5. Prepare a possible next step

If supported, deterministic tools calculate, simulate, validate policy, and prepare an inspectable unsigned request. The proposed path includes limits, expiry, dependencies, and reasons it may be blocked.

## 6. Review and authorise

The user or authorised enterprise approvers review the exact current state. If anything material changes, the prior review expires. The final signature remains outside the Agent.

The journey may end earlier. If evidence is insufficient, a contract cannot be verified, a source conflict remains material, the request falls outside policy, or the product does not support the action, the correct outcome is clarification, abstention, or refusal — not a fabricated completion.
