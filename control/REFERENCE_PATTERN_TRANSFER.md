# Reference Pattern Transfer

This internal map records how mature first-party documentation patterns were interpreted for Whale CeFi. It does not copy competitor wording or branding.

| # | Source pattern | Whale CeFi implementation |
|---:|---|---|
| 1 | Coinbase EEA agreement: exact entities, permissions, complaints, governing law | Entity and Service Register; Complaints and Appeals; Terms control |
| 2 | Coinbase custody terms: title and asset-use boundary | Customer Relationship and Asset Rights |
| 3 | Kraken EEA rewards terms: custody versus opt-in earning | Separate custody and earning legal states |
| 4 | Kraken proof of reserves: user inclusion and recurring epochs | Reserves and Liabilities plus proof-epoch schema |
| 5 | Coinbase service status | Component-level Service Status |
| 6 | Coinbase incident history | Append-only incident records and postmortems |
| 7 | Aave deployed-contract registry | Deployment Registry tied to explorer and bytecode |
| 8 | Aave Address Book | Machine-readable deployment and authority records |
| 9 | Circle token-address registry | Canonical asset + network + contract identity |
| 10 | Circle transparency reports | Funding, capacity, reserve, liability, and attestation snapshots |
| 11 | RFC 9116 | Canonical security.txt and vulnerability route |
| 12 | OpenAPI | Typed public API contract |
| 13 | AsyncAPI | Typed financial and operational event contract |
| 14 | JSON Schema 2020-12 | Validation contracts for every mutable registry |
| 15 | OpenAI system cards | WENI release identity, evaluations, limitations, and authority scope |
| 16 | ESMA service-perimeter clarity | Versioned regional eligibility and entity matrix |
| 17 | VARA lending/borrowing rule structure | Written product, custody, risk, and reporting perimeter |
| 18 | VARA written-agreement requirements | Immutable product consent and terms hash |
| 19 | Coinbase staking-rate presentation | Explicit distinction between fixed contractual and variable estimated return |
